# Quotation Online JCP

ระบบใบเสนอราคาออนไลน์ — Next.js 16 + TypeScript + Prisma 7 + PostgreSQL + Better Auth

- ความต้องการ: [docs/requirements.md](docs/requirements.md)
- สถาปัตยกรรมและลำดับงาน: [docs/architecture.md](docs/architecture.md)

## สถานะ

- **M0 เสร็จ**: ล็อกอิน, ลืมรหัสผ่าน, บังคับเปลี่ยนรหัสผ่านครั้งแรก, ล็อกบัญชีเมื่อผิด 5 ครั้ง, 2FA (บังคับผู้บริหาร/แอดมิน), จัดการผู้ใช้และบริษัท, ประวัติการแก้ไข, ไทย/อังกฤษ
- **M1 เสร็จ**: ลูกค้า (ผู้ดูแล, กันลูกค้าซ้ำ, ผู้ติดต่อ, ประวัติเปลี่ยนผู้ดูแล, รายการรอเลือกผู้ดูแล), สินค้า (ซ่อนราคาขั้นต่ำจากพนักงานขาย), นำเข้าลูกค้า/สินค้าจาก Excel
- **M2 เสร็จ**: ใบเสนอราคา (ออกเลขที่อัตโนมัติแยกบริษัท/เดือน, ส่วนลดรายบรรทัดและท้ายบิล, VAT, ยอดเงินตัวหนังสือไทย, เตือนรายการที่ต้องขออนุมัติ, ส่งลูกค้าแล้ว, แก้ไขเป็นฉบับใหม่ R1/R2, คัดลอก, ยกเลิก)
- **M3 เสร็จ**: PDF ใบเสนอราคาไทย/อังกฤษ (หัวกระดาษและโลโก้บริษัท, ลายเซ็นพนักงานขาย, ลายน้ำ "ฉบับร่าง"), เก็บ PDF ที่ส่งลูกค้าทุกฉบับ, ส่งอีเมลแนบ PDF จากระบบ (ในเครื่องพัฒนาเขียนลง `storage/outbox/` จนกว่าจะตั้ง Resend)
- **M4 เสร็จ**: ขออนุมัติราคาต่ำกว่าขั้นต่ำ, ผู้บริหารอนุมัติ/ไม่อนุมัติ/เสนอราคาใหม่ (หน้าพิจารณาใช้บนมือถือได้), แก้ราคาขึ้นหลังอนุมัติไม่ต้องขอใหม่, กระดิ่งแจ้งเตือนและอีเมล, เตือนคำขอค้างเกิน 4 ชั่วโมงทำการ (`/api/cron/approval-reminders`)
- **M5 เสร็จ**: บันทึกการติดตามระดับใบและระดับลูกค้าพร้อมวันนัดถัดไป, หน้าแรก "ต้องติดตามวันนี้ / เลยกำหนด" และ "ส่งแล้วไม่มีการติดตามเกิน 7 วัน", ได้งาน (เลขที่ PO + วันที่ + ไฟล์ PO) / ไม่ได้งาน (เหตุผล), หมดอายุอัตโนมัติเมื่อเลยวันยืนราคา
- **M6 เสร็จ**: ลูกค้าที่หายไป (ไม่มีการซื้อเกิน 6 เดือน ปรับได้ที่หน้าตั้งค่า) แจ้งผู้ดูแลทางกระดิ่ง หน้าแรก และอีเมลวันจันทร์, บันทึกผลการติดต่อ (ยังเป็นลูกค้า = พักเตือน 30 วัน / เสียลูกค้า), โอนลูกค้าพร้อมใบที่ยังเปิดอยู่ (ทีละรายหรือหลายราย หรือทั้งหมดของผู้ใช้ที่ลาออก), คำขอรับดูแลลูกค้าให้ผู้บริหารอนุมัติ, นำเข้าวันที่ขายล่าสุดจาก Express, งานรายวัน `/api/cron/daily`
- **M7 เสร็จ**: แดชบอร์ด (มูลค่าที่เสนอ, Won, อัตราปิดการขาย, เทียบเป้า, แยกพนักงานขาย/เดือน/บริษัท, กราฟ 12 เดือน, เหตุผลที่ไม่ได้งาน, สินค้าและลูกค้าที่เสนอบ่อย, ใบใกล้หมดอายุ), ตั้งเป้ายอดขายรายเดือน, รายงานพร้อม export Excel (รายการใบเสนอราคา, รายการ Won รายบรรทัดสำหรับบัญชี, ลูกค้าที่หายไป), ประวัติการแก้ไข (audit log) สำหรับผู้บริหารและแอดมิน และประวัติในหน้าใบเสนอราคา

## เริ่มพัฒนาในเครื่อง (Windows)

1. เปิดฐานข้อมูลสำหรับพัฒนา (embedded PostgreSQL, port 55433) แล้วเปิดค้างไว้

   ```powershell
   node $env:USERPROFILE\quotation-jcp-devdb\pg.mjs
   ```

2. ตั้งค่าครั้งแรก

   ```powershell
   Copy-Item .env.example .env   # แล้วใส่ BETTER_AUTH_SECRET
   npm install
   npm run db:deploy
   npm run db:seed:demo          # สร้างแอดมิน + ข้อมูลตัวอย่าง รหัสผ่านอยู่ใน .dev-credentials.txt
   ```

3. รันเว็บ: `npm run dev` แล้วเปิด http://localhost:3000

## คำสั่งที่ใช้บ่อย

| คำสั่ง | ใช้ทำอะไร |
|---|---|
| `npm run dev` | รันเว็บโหมดพัฒนา |
| `npm test` | unit test (Vitest) |
| `npm run typecheck` | ตรวจ TypeScript |
| `npm run lint` | ESLint |
| `npm run db:migrate` | สร้าง/รัน migration หลังแก้ `prisma/schema.prisma` |
| `npm run db:seed` | สร้างแอดมินคนแรก (ถ้ายังไม่มีผู้ใช้) |
| `node --env-file=.env tests/smoke/m5-followups.mjs` | smoke test หน้าแรก (รายการต้องติดตาม), สิทธิ์ดูการติดตามและไฟล์ PO, งานรายวัน (หมดอายุ + เตือน 7 วัน) และ CHECK constraint ของ Won/Lost (ต้องมี `CRON_SECRET` ใน .env และใบที่ส่งแล้วของ sales1 อย่างน้อย 1 ใบ ข้อมูลทดสอบถูกลบหลังรัน) |
| `node --env-file=.env tests/smoke/m7-reports.mjs` | smoke test ตัวเลขแดชบอร์ด/รายงาน/Excel ตรงกับข้อมูลทดสอบที่คิดด้วยมือ (ขอบเดือนเวลาไทย, ใบที่โอน, ใบยกเลิก, เป้า), สิทธิ์พนักงานขาย/ผู้บริหาร/แอดมิน (ต้องไม่มีใบเสนอราคาลงวันที่ปี 2024 ข้อมูลทดสอบถูกลบหลังรัน) |
| `node --env-file=.env tests/smoke/m6-dormant.mjs` | smoke test ลูกค้าที่หายไป: กระดิ่งครั้งเดียวต่อช่วง, หน้าแรกและรายการลูกค้าที่หายไป, สิ่งที่พนักงานขายคนอื่นเห็น, หน้าผู้บริหาร, อีเมลวันจันทร์ (outbox), แม่แบบ Express และ CHECK constraint (ต้องมี `CRON_SECRET` ข้อมูลทดสอบถูกลบหลังรัน) |
| `node --env-file=.env tests/smoke/m4-approvals.mjs` | smoke test สิทธิ์หน้าอนุมัติ/การแจ้งเตือน, endpoint cron, เตือนคำขอค้าง 1 รอบ (ต้องมี `CRON_SECRET` ใน .env และคำขออนุมัติของ sales1 อย่างน้อย 1 คำขอ) |
| `node --env-file=.env tests/smoke/m3-documents.mjs` | smoke test สิทธิ์ดาวน์โหลด PDF/รูปลายเซ็น, ไฟล์ใน storage ไม่เปิดสาธารณะ, PDF ที่ส่งแล้วตรงกับไฟล์ที่เก็บ (ต้องมีใบของ sales1 ที่ส่งลูกค้าแล้ว) |
| `node --env-file=.env tests/smoke/m2-quotations.mjs` | smoke test สิทธิ์ใบเสนอราคา (พนักงานขายคนอื่น/ผู้บริหาร/แอดมิน), ราคาขั้นต่ำไม่หลุด, เลขที่ไม่ซ้ำเมื่อยิงพร้อมกัน (ต้องมีใบเสนอราคาของ sales1 อย่างน้อย 1 ใบ) |
| `node --env-file=.env tests/smoke/m1-customers.mjs` | smoke test สิทธิ์การมองเห็นลูกค้า/ราคาขั้นต่ำของพนักงานขาย (ต้องนำเข้าข้อมูลทดสอบ M1 ก่อน) |
| `node --env-file=.env tests/smoke/m0-auth.mjs` | smoke test ล็อกอิน/สิทธิ์/การโจมตี (ต้องรันเว็บอยู่ และ seed demo ใหม่ก่อน ใช้เวลาประมาณ 2 นาที) |

## หมายเหตุ

- อีเมล (ลืมรหัสผ่าน) ยังไม่ส่งจริงจนถึง M3 — โหมดพัฒนาจะพิมพ์ลิงก์ไว้ใน console ของเซิร์ฟเวอร์
- `.env` และ `.dev-credentials.txt` ห้าม commit (อยู่ใน `.gitignore` แล้ว)
